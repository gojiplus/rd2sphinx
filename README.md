# rd2sphinx

`rd2sphinx` makes an R package look like a native Sphinx project.

It reads the package's generated `man/*.Rd` files through R's own Rd parser,
writes semantic Sphinx objects such as `.. r:function::`, bundles an R domain
for cross-references and `objects.inv`, and lets Sphinx handle themes, search,
builders, and deployment.

The intended pipeline is:

```text
roxygen comments → man/*.Rd → rd2sphinx → Sphinx R domain → Furo HTML
```

## Install

The delivery includes a source-package-layout tarball. This runtime could not
run `R CMD build`, so the r-canon CI rebuilds and checks the package from the
full source before using it. To try the supplied archive directly:

```r
install.packages(
  "rd2sphinx_0.0.0.9000.tar.gz",
  repos = NULL,
  type = "source"
)
```

After the package is added to `gojiplus/r-canon`:

```r
remotes::install_github("gojiplus/r-canon", subdir = "rd2sphinx")
```

## Use

From an R package root, first refresh the Rd files when the roxygen comments
have changed:

```r
roxygen2::roxygenise()
```

Then scaffold and build the site:

```r
rd2sphinx::use_sphinx(docs_dir = "sphinx-docs")
```

```sh
python -m pip install -r sphinx-docs/requirements.txt
```

```r
rd2sphinx::build_sphinx(
  docs_dir = "sphinx-docs",
  output_dir = "_site"
)
```

The generated `conf.py` uses Furo. Reference pages and the copied Sphinx
extension are generated inputs; HTML is written to `_site/`. None of these
need to be committed.

`render_sphinx()` can be called separately when Sphinx itself is run by shared
infrastructure:

```r
rd2sphinx::render_sphinx(
  docs_dir = "sphinx-docs",
  include = "exports"
)
```

```sh
sphinx-build -W --keep-going -b html sphinx-docs _site
```

## Common GitHub Actions infrastructure

The delivery contains a reusable workflow for `gojiplus/r-canon`. A package
repository can call it with a very small workflow:

```yaml
jobs:
  docs:
    uses: gojiplus/r-canon/.github/workflows/reusable-r-sphinx.yml@main
    with:
      docs-dir: sphinx-docs
      include: exports
      artifact-name: r-furo-site
```

The workflow builds with warnings treated as errors and uploads an ordinary
HTML artifact. The standalone workflow generated by `use_sphinx()` deploys on
non-PR builds, while the supplied Tuber pilot is deliberately safer: it only
replaces the existing Pages site after a manual run with `deploy=true`.

## What is semantic here?

The bundled Sphinx domain registers R functions, data objects, classes,
packages, and general help topics. Local Rd links become Sphinx cross-references,
objects appear in the general index and search, and Sphinx writes them to
`objects.inv`. Rendering is therefore not merely Rd-to-Markdown conversion.

## Current scope

The MVP supports function, data, class, package, and general Rd topics;
arguments; values; details; examples; local Rd links; exported-object
filtering; multiple usages; infix and replacement functions; and a native
Sphinx domain.

The main follow-on work is vignette/README/NEWS ingestion, richer Rd tables and
math edge cases, S3/S4/R6-specific presentation, and automatic discovery of
cross-package inventories.
